Две границы времени жизни

Borrowed

BackendMessage.Payload, DataRow fields, CopyData, auth data и IndexedDataRow ссылаются на память входа. Индексированная строка дополнительно заимствует переданный rowValues.

Owned metadata

GetRowDescription, GetDiagnostics, GetParameterStatus и другие metadata-accessors создают строки или массивы по требованию. Вызывайте accessor один раз и сохраняйте результат, когда он нужен повторно.

TryRead возвращает false при нехватке данных; невалидные framing / body вызывают InvalidDataException. В обоих случаях ref input не продвигается. При ошибке полного индексируемого DataRow часть reusable rowValues может уже измениться — его содержимое не имеет гарантии атомарности.
Parser определяет Kind и структуру сообщения. Связь ответа с запросом, допустимость неизвестного tag и обработку ErrorResponse → Sync → ReadyForQuery обеспечивает вызывающий код. Асинхронные NoticeResponse, ParameterStatus и NotificationResponse помечаются IsAsynchronous.

NULL / EMPTY

Три разных состояния

SQL NULL — внешний length=-1. Пустой scalar payload может иметь length=0. NULL элемента массива — внутренняя length=-1; пустой массив кодируется ndim=0 и 12-байтным заголовком.

Binary COPY: поток, framing и состояние

Три отдельные роли: кодировать tuples, упаковать CopyData и отследить завершение подпротокола.

COPY IN / OUT

BinaryCopyWriter · одна bigint-колонка

Байты COPY stream

Показан stream без внешних CopyData headers. 19 байт header; 14 байт на tuple с одним bigint; 2 байта trailer.

Только примитивы ядра

Запись в готовый Stream

using var frames = new CopyDataWriter(stream);
var tuples = new BinaryCopyWriter(frames, 1);

tuples.StartRow();
tuples.WriteInt64(42);
tuples.Complete();       // binary trailer
frames.WriteCopyDone(); // CopyData + CopyDone

// После фактической отправки:
operation.CopyDoneSent();
// Для Extended COPY IN отправьте новый Sync,
// затем вызовите operation.SyncSent().
// Принимайте ответы до operation.IsCompleted.

stream уже открыт, operation создан из CopyInResponse. Завершение writer не означает завершение команды сервера.

STREAM CODEC

BinaryCopyWriter / Reader

Writer: header → StartRow → field lengths / payload → trailer. Reader: TryReadHeader возвращает bool, TryReadRow — NeedMoreData, Row или Completed; строки заимствуют input и field storage.

FRAMING

CopyDataWriter

IBufferWriter поверх синхронного writable Stream. Pooled buffer, framing tag=d; WriteCopyDone объединяет последние данные и CopyDone. Dispose возвращает память и оставляет Stream открытым.

STATE

BinaryCopyOperation

Accept проверяет фазы Import / Export / Command / Ready / Recovery. Асинхронное сообщение возвращает false для внешней маршрутизации. Транспорт резервируется до IsCompleted.

В Extended COPY IN нужен новый Sync после data phase. Sync / Flush во время импорта сервер игнорирует. COPY BOTH распознаётся wire-parser, но BinaryCopyOperation поддерживает IN/OUT. Правила COPY ↗

Собрать группу Extended Query из примитивов

using System.Buffers;
using Mpgsql.Converters;
using Mpgsql.Protocol;

var output = new ArrayBufferWriter<byte>();
byte[] payload = new byte[Int64Converter.ByteCount];
Int64Converter.Write(42, payload);

FrontendMessageWriter.Write(FrontendMessage.Parse(
    "select $1::bigint", parameterTypes: new uint[] { 20 }), output);
FrontendMessageWriter.Write(FrontendMessage.Bind(
    parameters: new ReadOnlyMemory<byte>?[] { payload },
    parameterFormats: new[] { FormatCode.Binary },
    resultFormats: new[] { FormatCode.Binary }), output);
FrontendMessageWriter.Write(
    FrontendMessage.Describe(StatementOrPortal.Portal), output);
FrontendMessageWriter.Write(FrontendMessage.Execute(), output);
FrontendMessageWriter.Write(FrontendMessage.Sync(), output);

// output.WrittenMemory отправляет владелец транспорта.

В этом небольшом примере payload выделен отдельно для прозрачности Bind API. Другие кодирующие пути могут записывать payload прямо в конечный буфер.

IFrontendMessage<T>, typed frontend structs, raw messages, backend parser / accessors, scalar / array converters, Pg*-значения и COPY codec / state. Тип payload выбирается явным конвертером.

Внутренняя реализация

Общие механизмы

WireReader, WireWriter, WireEncoding, IBinaryCodec<T>, BinaryScalar, BinaryArray, BinaryNullableArray, BinaryReferenceArray и helper-код форматов не расширяют публичный контракт пакета.

Все модели этой страницы работают локально. Wire-байты вычисляются для фиксированных демонстрационных сообщений; схема и контракты сверены с рабочим деревом на 08.10.2026. Ссылки на исходники доступны, пока HTML лежит в docs рядом с проектом.
